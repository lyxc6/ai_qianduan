# 用户编码规范与重构指南

## 基础交互规则
1. 请用中文回答我
2. 如果回答的是代码，请给每个关键节点，比较难懂的代码增加中文注释
3. 当生成的代码行数超过20行时，请考虑聚合代码以及考虑其颗粒度是否适合
4. **强制使用Skill**：在执行任何前端开发、设计、构建相关任务时，必须首先检查可用的Skill工具，并在相关时立即调用适当的Skill工具。不得直接跳过Skill工具直接实现功能。

### Skill使用规范
- **前端设计任务**：必须使用 `frontend-design` Skill
- **项目规划任务**：必须使用 `writing-plans` Skill
- **测试驱动开发**：必须使用 `test-driven-development` Skill
- **代码审查**：必须使用 `requesting-code-review` Skill
- **系统调试**：必须使用 `systematic-debugging` Skill
- **安全审查**：必须使用 `TRAE-security-review` Skill

### 强制使用场景
1. 创建或修改前端界面、组件、页面时
2. 进行响应式布局和样式优化时
3. 设计UI/UX交互体验时
4. 制定开发计划和方案时
5. 进行代码重构和优化时

## 代码质量与重构规范

### 通用编码规范
1. 避免不必要的对象复制或克隆
2. 避免多层嵌套，提前返回
3. 使用适当的并发控制机制

### CSS/样式规范
1. **禁止使用px单位**
   - 高度使用 `vh`、百分比、`rem`
   - 宽度使用 `vw`、百分比、`rem`
   - 字体、间距使用 `rem`（基准16px）
   - 小尺寸使用 `em` 或 `rem`
2. 转换规则：16px = 1rem
3. 根元素字体大小设为16px作为基准

## 代码坏味道识别与处理
基于Martin Fowler《重构》一书的核心观点：

### 1. 神秘命名
- 问题：变量、函数、类或模块的名称不能清晰表达其用途
- 处理：重命名为具有描述性的名称，使代码自解释

### 2. 重复代码
- 问题：相同或相似的代码出现在多个地方
- 处理：提取为函数、类或模块；应用模板方法模式

### 3. 过长函数
- 问题：函数过长，难以理解和维护
- 处理：提取函数，将大函数分解为多个小函数
